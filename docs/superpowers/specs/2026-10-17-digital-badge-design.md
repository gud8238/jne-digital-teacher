# 교원 AI·디지털역량 디지털배지 웹앱 설계서

작성일: 2026-10-17 (Asia/Seoul)

상태: 사용자 검토용. 대화에서 확인한 방향을 구체화한 설계이며, 제품 구현과 배포는 아직 시작하지 않았다.

## 1. 목적과 성공 기준

전남광주통합특별시교육청 교원이 자신의 AI·디지털역량 배지 현황과 다음 성장 경로를 확인하는 반응형 프로토타입을 제작한다. 제공한 PC·모바일 디자인과 배지·심볼 이미지를 사용한다. 구글시트를 데이터베이스로 사용하며 Google Apps Script(GAS)의 `doGet`으로 데이터를 조회한다.

성공 기준은 다음과 같다.

1. 시트에 등록한 나이스번호와 이름이 모두 일치할 때 로그인한다.
2. 로그인한 교원 자신의 배지 상태와 취득일을 나의 배지함에 표시한다.
3. 배지소개에서 7개 배지를 클릭하거나 터치하여 시트에 저장한 설명과 기준을 읽는다.
4. 인증안내에서 동일한 개인 데이터로 달성 현황과 추천 성장경로를 표시한다.
5. PC와 모바일에서 제공한 각 화면의 구성을 구현하고 가로 넘침 없이 조작한다.
6. 로컬 검증 후 GitHub CLI/Git CLI로 지정 저장소에 push하고 Netlify CLI로 배포한다.

## 3. 선택한 구조

React + TypeScript + Vite로 프런트엔드를 만들고 Netlify에 정적 배포한다. 동일 출처의 Netlify Function이 GAS 웹앱을 호출한다. GAS가 지정 구글시트를 읽는다.

흐름: 브라우저 → `/api/*` Netlify Function → GAS `doGet(e)` → Google Sheets.

대안인 브라우저의 GAS 직접 호출은 외부 출처 응답·리다이렉트와 개인 조회 자격정보 처리가 화면 코드에 들어간다. 중계 함수를 사용하면 브라우저는 동일 출처 API만 다루고 GAS 연결 정보·공유 비밀값은 서버 환경에 둘 수 있다. 사용자 지정 DB와 API는 그대로 유지한다.

프런트엔드는 화면, 공통 UI, API 클라이언트, 배지 상태 계산을 분리한다. 중계 함수는 입력 검사·쿠키·응답 변환을 맡고, GAS는 시트 읽기·로그인 검증·세션 검증을 맡는다. 배지 달성률·마스터 조건·추천 정렬에는 한 가지 명시적 규칙을 사용하고 테스트로 검증한다.

## 4. 화면과 이동

### 공통

- `/`: 메인 및 로그인.
- `/badges`: 배지소개. 로그인 없이 열람 가능.
- `/guide`: 인증안내. 공개 기준은 열람 가능하고 개인 로드맵은 로그인 후 표시.
- `/my-badges`: 나의 배지함. 미로그인 시 로그인으로 이동하고 성공 후 원래 화면으로 복귀.
- PC는 시안의 상단 헤더와 메뉴를 사용한다. 로그인 후 로그인 버튼 위치에 이름과 로그아웃 동작을 제공한다.
- 모바일은 시안의 카드 목록·3열 배지함·하단 내비게이션 구성을 따른다. 하단 메뉴는 실제 제작 범위인 홈, 배지소개, 인증안내, 나의 배지함 4개로 구성한다. 별도 마이페이지·설정·알림 기능은 추가하지 않는다.
- 키보드 포커스, 이미지 대체 텍스트, 입력 레이블, 터치 영역과 화면 낭독 상태를 제공한다. 상태를 색상으로만 구분하지 않는다.

### 메인 및 로그인

- PC는 왼쪽 성장 메시지·인물 비주얼과 오른쪽 로그인 카드, 아래쪽 주요 메뉴 카드 3개를 배치한다.
- 모바일은 교육청 심볼, 메시지, 인물 비주얼과 세로 로그인 버튼을 배치한다.
- 로그인 수단은 정확히 두 개다: `아이모두계정으로 로그인`, `이메일로 로그인`.
- 아이모두 버튼은 표시만 구현한다. 누르면 `아이모두 로그인은 준비 중입니다.`라는 안내를 표시하고 인증 요청이나 세션을 만들지 않는다.
- 이메일 로그인 하단에 작은 글씨로 `구글시트 테스트버전`을 표시한다.
- 이메일 로그인을 누르면 나이스번호와 이름 입력 폼을 연다. 이메일 주소나 비밀번호는 요구하지 않는다.
- 나이스번호는 문자열로 처리하고 앞의 0을 보존한다. 양 끝 공백만 제거한다. 이름도 양 끝 공백만 제거하고 일치 여부를 검사한다.
- 성공하면 나의 배지함으로 이동한다. 실패 시 `나이스번호와 이름을 확인해 주세요.`를 표시한다. 조회 중 중복 제출을 막고 오류 후 다시 입력할 수 있다.
- Google 로그인·게스트 로그인 버튼은 만들지 않는다. 배지소개는 상단 메뉴 또는 주요 메뉴 카드로 공개 접근한다.

### 배지소개

- PC는 인물·구름 배경, 3단계 성장 체계, 7개 배지 선택 카드와 하단 상세 설명을 배치한다.
- 모바일은 전체·입문·전문가·마스터 필터와 세로 배지 목록을 배치한다.
- 배지 선택 시 이름, 단계, 설명, 취득 기준, 기준 확정 상태를 보여준다. PC에서는 하단 상세 영역, 모바일에서는 펼침 영역 또는 하단 패널로 표시한다.
- 배지 설명은 시트 응답을 사용한다. API 오류를 정적 설명으로 숨기지 않고 재시도 UI를 제공한다.

### 나의 배지함

- 이름, 소속 학교, 전체 획득 수 `/7`, 전문가 획득 수 `/5`, 전체 달성률과 마스터까지 남은 전문가 배지 수를 표시한다.
- PC는 시안처럼 입문, 전문가, 마스터 단계를 세로로 나누고 오른쪽에 배지를 배치한다.
- 모바일은 프로필·요약 카드 아래에 3열 배지 카드를 표시한다.
- 획득 배지는 원색·체크·획득일로, 미획득 배지는 회색 처리·잠금·미획득 문구로 표시한다. 회색 처리는 기존 PNG에 CSS 필터를 적용한다.
- 전체·획득·미획득·마스터 필터는 실제 배지 데이터로 작동한다. 필터 결과가 없으면 해당 상태를 설명한다.
- 배지를 선택하면 그 배지 설명과 내 상태를 확인한다. 인증안내 이동 버튼으로 다음 성장 경로를 확인한다.
- 소속 학교가 빈 값이면 학교 줄을 생략하고 임의 학교명을 넣지 않는다. 취득일이 없는 획득 기록은 `취득일 미등록`으로 표시한다.

### 인증안내

- PC는 상단 개인 성장 로드맵, 왼쪽 7개 배지 달성 목록, 오른쪽 추천 성장경로를 배치한다.
- 모바일은 시안처럼 성장 로드맵, 현황 목록과 추천 활동 카드를 세로 배치한다.
- 로그인 전에는 전체 체계·공개 기준과 개인 현황 확인용 로그인 버튼을 표시한다.
- 로그인 후 현재 전문가 획득 수와 3종 조건까지 남은 수를 표시한다.
- 추천 항목은 미획득 전문가 배지를 시트의 추천 우선순위로 정렬한다. 초기 순서는 전문과정 이수자, 에듀테크 전문가, 수업연구 실천가, 강의 선도자, 현장코칭 전문가로 둔다.
- 개인 연수 이력이나 활동 증빙을 수집하지 않으므로, 추천은 미획득 여부와 기본 순서에 따른 안내임을 표시한다. 사용자별 취득 난이도나 심사 가능성을 추정하지 않는다.
- `기준 보기` 또는 `도전 준비하기`는 배지 설명과 준비 항목을 연다. 실제 신청·심사·연수 신청을 접수하지 않는다.
- 세부 기준과 공식 신청·심사·발급 절차가 추후 확정 예정이라는 안내를 표시한다.

| master | 3 | 역량 마스터 | 전문가 배지 3종 이상 획득. 세부 인증·발급 절차는 추후 확정 |

설명은 위 기준을 자연스러운 문장으로 풀어 시트에 저장한다. 원문이 서로 다른 활동의 관계를 확정하지 않은 경우 엄격한 AND 조건이나 시간·횟수 기준을 임의로 추가하지 않는다.

- 전체 획득 수: 서로 다른 7개 badge_id 중 `획득` 상태의 수.
- 전문가 획득 수: 단계 2인 5개 badge_id 중 `획득` 상태의 수.
- 전체 달성률: `Math.round(전체 획득 수 / 7 * 100)`.
- 전문가 달성률: `Math.round(전문가 획득 수 / 5 * 100)`.
- 마스터 조건까지 남은 수: `Math.max(0, 3 - 전문가 획득 수)`.
- 마스터 조건 충족과 마스터 발급은 구분한다. 전문가 3종을 모아도 수집현황에 마스터 획득 기록이 없으면 마스터를 자동 발급하지 않는다. `조건 충족 · 발급 전`으로 안내한다.
- 이미 마스터를 획득한 사람은 `마스터 달성`으로 표시하고 추가 획득 권유를 강제하지 않는다.
- 동일 교원·동일 배지의 중복 행이나 정의되지 않은 상태는 데이터 오류로 처리한다. 불완전한 응답을 미획득으로 간주하지 않는다.
- 일관성을 위해 초기 테스트 데이터는 교원당 7개 상태 행을 갖춘다.

## 6. 구글시트 구조

제공된 스프레드시트를 그대로 사용한다. `시트1`은 유지하고 필요한 탭을 추가한다. 추가 전 메타데이터와 대상 셀을 다시 읽어 기존 내용과 충돌하지 않는지 확인한다.

| 탭 | 열 | 내용 |
| --- | --- | --- |
| 교원 | teacher_id, 나이스번호, 이름, 소속학교, 활성여부 | teacher_id는 공개 조회용 내부 ID. 나이스번호는 텍스트 서식. 활성여부는 사용/중지 |
| 배지소개 | badge_id, 단계, 배지명, 설명, 취득기준, 준비안내, 추천우선순위, 기준상태, 표시순서 | 7개 정의. 기준상태는 잠정 기준. 이미지는 로컬 asset 매핑을 사용 |
| 배지별 수집현황 | teacher_id, badge_id, 수집현황, 취득일 | 수집현황은 획득/미획득. 취득일은 YYYY-MM-DD 또는 빈 값 |

테스트 데이터는 실제 교원으로 오인되지 않게 `테스트교원01` 등의 이름과 `테스트학교`를 사용한다. 서로 다른 나이스번호와 별도의 내부 ID를 사용하고, 최종 안내에 로그인용 테스트 값을 제공한다. 실사용자 나이스번호·이름·수집현황을 GitHub나 정적 FE 파일에 포함하지 않는다.

대표 시나리오는 획득 0개, 입문+전문가 2개, 전문가 3개 이상이지만 마스터 발급 전, 마스터 획득 완료를 포함한다. 날짜·소속·획득수는 시나리오에 맞게 일관된 가상 값으로 구성한다.

## 7. API 계약과 세션

### 브라우저와 Netlify Function

| 메서드·경로 | 요청 | 응답 |
| --- | --- | --- |
| GET /api/badges | 없음 | 공개 배지 정의 7개 |
| POST /api/login | JSON: neisNumber, name | 본인 프로필, 세션 쿠키 |
| GET /api/me | HttpOnly 세션 쿠키 | 본인 프로필과 7개 수집현황 |
| POST /api/logout | 세션 쿠키 | 서버 세션 폐기와 쿠키 제거 |

인증안내와 나의 배지함은 같은 `/api/me` 데이터로 렌더링해 화면별 수치를 일치시킨다. 로그아웃 시 화면 메모리의 개인 데이터도 비운다. 새로고침 시 유효한 쿠키가 있으면 개인 정보를 다시 조회한다.

공통 성공 응답은 `{ ok: true, data: ... }`, 실패 응답은 `{ ok: false, error: { code, message } }`를 사용한다. 입력 오류 400, 로그인 실패·세션 만료 401, 잘못된 메서드 405, 데이터 오류 502, 외부 서비스 오류 503으로 구분한다. 브라우저에는 스택·시트 전체 행·나이스번호 목록을 보내지 않는다.

### Netlify Function과 GAS

- 모든 시트 조회와 로그인 대조는 GAS `doGet(e)`를 통해 수행한다.
- action은 `badges`, `login`, `me`, `logout`만 허용한다.
- 브라우저의 POST 로그인 입력은 중계 함수가 GAS doGet 요청으로 변환한다. 브라우저 주소·정적 번들에는 나이스번호 조회 URL이 들어가지 않는다.
- GAS는 `ContentService` JSON을 반환한다. 중계 함수는 Google 응답 리다이렉트를 따라간다. HTML 로그인 페이지나 비정상 응답은 API 오류로 처리한다.
- 웹앱은 배포자 권한으로 실행한다. 익명 접근 가능한 실행 URL에는 서버끼리 공유하는 비밀값 검증을 적용하고 값은 GAS Script Properties와 Netlify 환경변수에만 저장한다.
- 로그인은 시트의 활성 교원 행에 대해 나이스번호·이름 모두를 대조한다. 전체 교원 명단을 반환하지 않는다.
- 성공 시 예측 불가능한 세션 토큰을 발급하고 GAS 서버에 teacher_id와 만료를 연결한다. 세션 최대 수명은 4시간이다. 캐시 등 서버 세션 저장소에서 세션을 찾지 못하면 재로그인을 요청한다.
- 브라우저 쿠키는 HttpOnly, SameSite=Lax, Path=/를 사용한다. 배포 환경에서는 Secure를 적용하고 로컬 HTTP 테스트에서만 Secure를 생략한다.
- 나이스번호·이름은 로그인 요청을 처리한 후 FE 영속 저장소에 보관하지 않는다. 인증 상태를 localStorage의 임의 플래그로 대신하지 않는다.
- 개인 데이터 응답은 `Cache-Control: no-store`로 제공한다. 공개 배지 설명만 짧게 캐시할 수 있다.

## 8. 이미지와 반응형 규칙

| 역할 | 원본 |
| --- | --- |
| 배지 7종 | `AI디지털 입문자.png`, `에듀테크 전문가.png`, `전문과정 이수자.png`, `수업연구 실천가.png`, `강의 선도자.png`, `현장코칭 전문가.png`, `역량 마스터.png` |
| 헤더·모바일 심볼 | `전남광주통합특별시 가로심볼.png`, `전남광주통합특별시 심볼.png` |
| PC 화면 구조 | `메인페이지(로그인 겸).png`, `배지소개 페이지.png`, `인증안내 페이지.png`, `나의 배지함 페이지.png` |
| 모바일 화면 구조 | `웹엡 디자인레퍼런스(모바일버전).png` |

- 배지와 심볼의 비율·원본 색상을 유지한다. 배지 원본에 이름이 포함되어 있으므로 표시 크기를 확인해 카드 이름과 시각적으로 충돌하지 않게 배치한다.
- 인물·구름·책 등은 페이지 시안에 합쳐져 있다. 필요한 장식 영역은 제공 이미지의 해당 부분을 CSS로 잘라 보여주는 방식으로 재사용한다. 로그인 버튼·카드·글자를 통째로 이미지로 대체하지 않는다.
- 구름 배경·그라데이션·패널·진행 막대·간단한 아이콘은 HTML/CSS/SVG로 구현한다. 별도 래스터 이미지 생성은 하지 않는다.
- PC는 넓은 콘텐츠 영역과 가로 배지 체계, 태블릿은 간격과 열 수를 줄이고, 모바일은 제공 시안의 목록·3열 배지함으로 전환한다.
- 360px, 390px, 768px, 1440px에서 검증한다. 모바일 하단 고정 메뉴와 안전영역만큼 본문 하단 공간을 확보한다.
- 실제 API 데이터가 길어져도 텍스트 잘림·카드 겹침·가로 스크롤이 생기지 않게 한다. 시스템 접근성 글자 확대와 reduced-motion 설정을 존중한다.

## 9. 로딩과 오류

- 배지 정의·개인 현황을 불러오는 동안 해당 영역에 로딩 상태를 표시한다.
- 로그인 실패와 외부 API 실패를 구분하고, 외부 API 실패에는 다시 시도 버튼을 제공한다.
- 시트 데이터 누락이나 GAS 미연결 상태를 가짜 성공·가짜 사용자·정적 대체 데이터로 감추지 않는다.
- 로컬 테스트용 fixture는 자동 테스트 안에서만 사용한다. 사용자가 보는 기본 실행은 실제 API 연결을 사용한다.
- 없는 경로는 안내 화면 또는 홈 복귀를 제공한다. Netlify SPA 리다이렉트는 새로고침한 하위 경로도 열리도록 구성하되 `/api/*`를 가리지 않는다.

## 10. 검증과 배포 완료 기준

### 자동 검증

- 나이스번호 앞자리 0 보존, 공백 처리, 불일치·비활성 교원 로그인 거절.
- 세션 없이 개인 조회 거절, 타인 ID로 조회 불가, 만료·로그아웃 후 조회 거절.
- 획득수·전문가수·반올림 달성률, 전문가 2/3종 경계, 마스터 발급 전·발급 완료 상태.
- 추천 목록에서 획득 배지를 제외하고 기본 우선순위에 따라 정렬.
- 중복 상태·배지 누락·알 수 없는 배지 ID·외부 HTML 응답·API 실패 처리.
- TypeScript 검사, 린트, 제품 빌드.

### 실제 연결·브라우저 검증

- 가상 테스트 교원을 시트에 저장하고 GAS 응답 및 웹앱 로그인을 실제로 확인한다.
- 테스트 계정 2개 이상을 번갈아 로그인해 개인 현황 분리를 확인한다.
- 배지소개 7개 선택, 나의 배지함 필터, 인증안내 이동과 추천 안내를 조작한다.
- PC·모바일 스크린샷으로 제공 시안과 배치·이미지·여백·글자 크기를 비교한다.
- 키보드 이동, 입력 오류, 세션 복원·로그아웃과 모바일 가로 넘침을 확인한다.

### 배포

1. GAS 소스와 설정 예시를 저장소에 보관하고 자격증명·실제 세션·비밀 환경변수는 제외한다.
2. 시트 변경 내용을 다시 읽어 헤더·배지 정의·가상 테스트 데이터가 의도대로 들어갔는지 확인한다.
3. Google CLI 인증 상태를 확인하고 GAS 프로젝트·배포를 구성한다. 브라우저 계정 동의가 필요한 경우 구체적인 동의 화면과 이유를 사용자에게 알린다.
4. 로컬 검증을 통과한 결과만 지정 GitHub 저장소의 main 브랜치에 CLI로 push한다.
5. Netlify CLI로 프로젝트를 생성 또는 연결하고 서버 환경변수를 설정한 뒤 빌드 결과를 배포한다.
6. 배포된 URL에서 로그인·개인 현황·배지 설명·모바일 화면을 다시 확인한다.
7. 최종 안내에 실제 배포 URL, GitHub URL, 가상 테스트 로그인 값, 검증 결과와 실제 사용에 영향을 주는 남은 제한을 제공한다.
