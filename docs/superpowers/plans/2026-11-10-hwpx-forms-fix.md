# HWPX 인식 오류와 인증서류 6종 양식 보완

> 실행: 기존 전용 작업 폴더의 codex/hwpx-forms-fix 브랜치에서 수행한다. 사용자 상세 요청을 설계 기준으로 삼고 별도 승인 질문 없이 구현·검증·배포한다.

## 설계와 범위

브라우저가 .hwpx 파일에 붙이는 MIME 문자열은 환경마다 다르다. 현재 Windows/Chrome은 application/haansofthwpx를 반환하며 FE 허용 목록에서 누락돼 파일 선택 직후 거절된다. FE는 지원 확장자·빈 파일·20MiB 제한을 확인하고, 서버는 확장자로 MIME을 정규화한 뒤 GAS에서 실제 파일 시그니처와 HWPX 구조를 검증한다. 페이지당 조회 1회와 기존 전송·접근 제어는 유지한다.

안내 문구는 사용자 지정 ‘파일 1개, 최대 20Mb’로 바꾸고 실제 한도 20×1024×1024바이트는 유지한다. 6종 업로드는 기존 공통 경로를 사용하며 모든 badgeId로 실제 연동을 검증한다. 이미 획득한 배지는 재신청하지 않는다.

양식은 기존 전문과정 예시를 포함한 6종을 통일한다. 흑백 공문서 형식, 신청자 정보는 이름(옆에 서명용 (인)), 연수원 아이디, 소속학교만 둔다. 배지별 E열 기준을 그대로 표시하고 해당 기준의 증빙 사진을 붙일 수 있는 편집 가능한 표를 만든다. 복수 기준은 별도 증빙 면으로 나누며 해당하는 내용만 첨부하도록 안내한다. 아직 확정되지 않은 세부 요건을 새로 만들지 않는다.

- [x] 문구 변경, 6종 UI와 마스터 제외·획득 제외 확인. GAS 경로도 전체 badgeId 검사.
- [x] 별도 문서 담당자가 artifacts/forms-v2에 네이티브 HWPX 6종 생성. 한글 열기·PDF 출력·XML·시각 검수. root는 코드·업로드 연동 담당.
- [x] Drive의 기존 professional 파일은 같은 ID로 갱신하고 나머지 5개를 서류양식 폴더에 추가. 중복 접두어 방지 및 API 다운로드 바이트 확인.

## 검토 초점

OS별 MIME 변화가 지원 문서를 거절하지 않는지, 확장자만 바꾼 가짜 파일은 서버에서 계속 거절하는지, 6개 업로드가 각각 올바른 비공개 폴더/시트 열로 연결되는지, 양식에 불필요한 개인정보 필드가 없는지, 미확정 취득기준을 발급 조건처럼 단정하지 않는지 확인한다.
